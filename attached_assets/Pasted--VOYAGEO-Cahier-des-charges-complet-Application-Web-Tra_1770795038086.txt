# 🌴 VOYAGEO — Cahier des charges complet
## Application Web Travel Planner sur mesure

---

## 1. VISION PRODUIT

### Concept
Voyageo est une web app destinée aux **travel planners indépendants** qui créent des itinéraires sur mesure pour leurs clients. L'app sert à la fois de :
- **Outil de création** pour le travel planner (admin) avec assistance IA
- **Expérience client** premium — le client reçoit un lien vers son voyage personnalisé, consultable comme une app mobile

### Proposition de valeur
- Le travel planner crée des voyages enrichis de ses **bons plans personnels** 🔥 (spots secrets, avis perso, tips d'initié)
- Le client a une app interactive dans sa poche : itinéraire, carte, budget, checklist, météo, liens de réservation
- L'IA (Claude API) accélère la création d'itinéraires que le planner personnalise ensuite

### Utilisateurs
| Rôle | Description | Accès |
|------|-------------|-------|
| **Admin (Travel Planner)** | Crée, édite, publie des voyages | Dashboard admin, éditeur IA, gestion clients |
| **Client** | Consulte son voyage, suit son budget, coche sa checklist | Vue voyage read-only + saisie dépenses |

## 2. STACK TECHNIQUE

### Frontend
- **Framework** : Next.js 14+ (App Router)
- **Styling** : Tailwind CSS
- **Cartes** : Leaflet.js avec tiles CartoDB dark
- **Graphiques** : Recharts
- **Icônes** : Lucide React
- **Fonts** : Nunito (body) + Playfair Display (titres)

### Backend & BDD
- **Auth** : Supabase Auth (email/password + magic links)
- **Base de données** : Supabase PostgreSQL
- **Storage** : Supabase Storage (photos custom uploadées par l'admin)
- **API IA** : Anthropic Claude API (claude-sonnet-4-20250514)

### APIs externes
- **Météo** : OpenWeatherMap API (gratuit, 1000 appels/jour)
- **Images par défaut** : Unsplash API (photos de villes/destinations)
- **Cartes** : OpenStreetMap via Leaflet (gratuit)

### Hébergement
- **Replit** pour le développement et MVP
- Migration ultérieure possible vers Vercel (frontend) + Supabase cloud

## 3. ARCHITECTURE BASE DE DONNÉES

### Table `profiles`
```
id              UUID (FK auth.users)
email           TEXT
name            TEXT
role            ENUM ('admin', 'client')
avatar_url      TEXT (nullable)
created_at      TIMESTAMP
```

### Table `trips`
```
id              UUID (PK)
created_by      UUID (FK profiles — l'admin qui l'a créé)
client_id       UUID (FK profiles — le client assigné, nullable)
title           TEXT ("Thaïlande Explorer")
subtitle        TEXT ("12 jours d'aventure tropicale")
destination     TEXT ("Thaïlande")
cover_emoji     TEXT ("🌴")
cover_image_url TEXT (nullable — photo custom ou Unsplash)
departure_date  DATE
return_date     DATE
total_budget    INTEGER (en euros)
currency        TEXT (défaut "€")
travelers       INTEGER
status          ENUM ('draft', 'active', 'archived')
share_token     TEXT UNIQUE (token pour lien de partage public)
created_at      TIMESTAMP
updated_at      TIMESTAMP
```

### Table `trip_days`
```
id              UUID (PK)
trip_id         UUID (FK trips)
day_number      INTEGER
date_label      TEXT ("15 Mars")
city            TEXT ("Bangkok")
color           TEXT ("#FF6348" — couleur du jour dans l'UI)
sort_order      INTEGER
created_at      TIMESTAMP
```

### Table `activities`
```
id              UUID (PK)
day_id          UUID (FK trip_days)
time            TEXT ("10:00")
title           TEXT ("Wat Pho — Bouddha couché")
icon            TEXT ("landmark")
duration        TEXT ("2h")
cost            DECIMAL (en euros, par personne)
type            ENUM ('activity','food','hotel','transport','shopping','nightlife')
note            TEXT (description/conseil)
is_personal     BOOLEAN (true = bon plan 🔥 du travel planner)
latitude        DECIMAL (nullable)
longitude       DECIMAL (nullable)
booking_url     TEXT (nullable — lien Booking, Airbnb, etc.)
sort_order      INTEGER
created_at      TIMESTAMP
```

### Table `day_tips`
```
id              UUID (PK)
day_id          UUID (FK trip_days)
content         TEXT ("Le BTS Skytrain est le plus rapide")
sort_order      INTEGER
```

### Table `day_budgets`
```
id              UUID (PK)
day_id          UUID (FK trip_days)
hotel           DECIMAL
food            DECIMAL
transport       DECIMAL
activities      DECIMAL
other           DECIMAL
```

### Table `expenses` (dépenses réelles du client)
```
id              UUID (PK)
trip_id         UUID (FK trips)
user_id         UUID (FK profiles — le client)
day_number      INTEGER
category        ENUM ('hotel','food','transport','activities','other')
amount          DECIMAL
note            TEXT (nullable)
created_at      TIMESTAMP
```

### Table `checklist_items`
```
id              UUID (PK)
trip_id         UUID (FK trips)
category        TEXT ("📄 Documents")
text            TEXT ("Passeport valide 6 mois")
is_critical     BOOLEAN
sort_order      INTEGER
```

### Table `checklist_checks` (état coché par le client)
```
id              UUID (PK)
checklist_item_id UUID (FK checklist_items)
user_id         UUID (FK profiles)
checked         BOOLEAN
checked_at      TIMESTAMP
```

### Row Level Security (Supabase RLS)
```
— Les admins voient tous les trips qu'ils ont créés
— Les clients voient uniquement les trips qui leur sont assignés
— Les dépenses et checks sont privés par user_id
— Le share_token permet un accès read-only sans auth
```

### 4.4 — ÉDITEUR DE VOYAGE (Admin) ⭐ Screen principal

**Route** : `/admin/trips/[id]/edit`

**2 onglets** :

#### Onglet 🤖 Assistant IA
- Interface chat avec Claude API
- Prompts suggérés en pills cliquables :
  - "Génère X jours pour [destination] avec budget détaillé"
  - "Ajoute 2 jours plage et farniente"
  - "Ajoute 1 jour temples et culture"
  - "Ajoute 1 jour street food et marchés"
  - "Réorganise le jour 3 pour optimiser les déplacements"
  - "Propose des alternatives moins chères pour le jour 5"
- L'IA génère des jours complets en JSON (activités, coordonnées GPS, budget, tips)
- Les jours générés sont ajoutés au voyage et sauvegardés en BDD
- Message de confirmation avec compteur de jours créés

**Prompt système pour l'IA** :
```

[X] jours existent déjà.

RÉPONDS UNIQUEMENT en JSON valide sans markdown :
{
  "days": [{
    "day": 1,
    "date": "Jour 1",
    "city": "Ville",
    "activities": [{
      "time": "10:00",
      "title": "Nom du lieu",
      "icon": "camera|food|hotel|transport|plane|shopping|landmark|beach|nature|nightlife",
```

#### Onglet 📅 Jours (édition manuelle)

  - Clic → ouvre le détail du jour

## 5. FEATURES TRANSVERSALES

### 5.1 — Météo en temps réel
- API OpenWeatherMap appelée par ville et par date
- Affichée dans le header de chaque jour et sur l'accueil
- Données : température, condition, icône, vent
- Cache des résultats (1 appel par ville par jour max)

### 5.2 — Liens Google Maps
- Chaque activité avec coordonnées a un bouton "Google Maps"
- Format : `https://www.google.com/maps/search/?api=1&query={lat},{lng}`
- Ouvre l'app Google Maps sur mobile

### 5.3 — Liens de réservation
- Champ optionnel `booking_url` sur chaque activité
- Bouton "Réserver" affiché si l'URL existe
- Ouvre dans un nouvel onglet

### 5.4 — Système de notifications (in-app)
- Toast notification en haut de l'écran
- Slide-down animation
- Types : success (vert), error (rouge)
- Auto-dismiss après 3 secondes
- Utilisé pour : sauvegarde, ajout dépense, génération IA, copie lien

### 5.5 — Export PDF
- Bouton "📥 Télécharger PDF" dans la vue client
- Génère un PDF propre avec :
  - Page de couverture (titre, dates, destination)
  - 1 page par jour (activités, horaires, notes, tips)
  - Page budget récapitulatif
  - Checklist
- Librairie : `@react-pdf/renderer` ou `jsPDF` + `html2canvas`

### 5.6 — Partage
- Bouton "🔗 Partager" dans la vue client
- Copie le lien `[domain]/trip/[share_token]` dans le presse-papier
- Option : partage natif mobile (Web Share API si disponible)

### 5.7 — PWA (Progressive Web App)
- Manifest.json avec icône Voyageo
- Service Worker pour le cache offline basique
- "Add to Home Screen" sur mobile
- Le client peut installer l'app sur son téléphone

## 7. SÉCURITÉ

### Authentification
- Supabase Auth avec email/password
- Magic link optionnel
- JWT tokens gérés automatiquement par Supabase
- Refresh tokens pour sessions persistantes

### Autorisation (RLS)
- Admin : CRUD sur ses propres trips, activités, jours
- Client : READ sur ses trips assignés, WRITE sur expenses et checklist_checks
- Public (share_token) : READ-ONLY sur le trip correspondant

### Protection
- Rate limiting sur l'API Claude (max 10 générations/heure/admin)
- Validation des inputs côté serveur (Next.js API routes)
- Sanitization des données avant insertion en BDD
- CORS configuré pour le domaine uniquement
- Variables d'environnement pour toutes les clés API

## 9. PROMPT REPLIT — À COPIER POUR LANCER LE PROJET

```
Crée une application web Next.js 14 (App Router) appelée "Voyageo" — un travel planner
sur mesure avec les specs suivantes :

STACK :
- Next.js 14 App Router + TypeScript
- Tailwind CSS (thème dark custom)
- Supabase (Auth + PostgreSQL + RLS)
- Leaflet.js pour les cartes interactives
- Recharts pour les graphiques budget
- Lucide React pour les icônes
- Anthropic Claude API pour la génération IA d'itinéraires

BASE DE DONNÉES (Supabase) :
- Table profiles (id, email, name, role admin/client)
- Table trips (id, created_by, client_id, title, subtitle, destination, cover_emoji,
  cover_image_url, departure_date, return_date, total_budget, currency, travelers,
  status draft/active/archived, share_token unique)
- Table trip_days (id, trip_id, day_number, date_label, city, color, sort_order)
- Table activities (id, day_id, time, title, icon, duration, cost, type, note,
  is_personal boolean, latitude, longitude, booking_url, sort_order)
- Table day_tips (id, day_id, content, sort_order)
- Table day_budgets (id, day_id, hotel, food, transport, activities, other)
- Table expenses (id, trip_id, user_id, day_number, category, amount, note)
- Table checklist_items (id, trip_id, category, text, is_critical, sort_order)
- Table checklist_checks (id, checklist_item_id, user_id, checked, checked_at)
- Row Level Security : admins voient leurs trips, clients voient les trips assignés

2 RÔLES :
1) Admin (travel planner) : crée des voyages, utilise l'IA pour générer des
   itinéraires, ajoute ses "bons plans perso" 🔥, assigne à un client
2) Client : consulte son voyage (itinéraire, carte, budget, checklist), saisit
   ses dépenses réelles

PAGES :
- / : Login (Supabase Auth)
- /admin : Dashboard admin (stats, liste voyages, actions)
- /admin/trips/new : Formulaire création voyage
- /admin/trips/[id]/edit : Éditeur avec onglet IA (chat Claude) + onglet Jours
  (édition manuelle des activités, toggle bon plan 🔥)
- /client : Dashboard client (liste de ses voyages)
- /client/trips/[id] : Vue voyage complète avec 5 onglets bottom nav :
  Accueil (hero photo + countdown + stats + programme),
  Carte (Leaflet dark avec markers emoji et polylines),
  Jours (timeline d'activités avec expand, filtre par ville, swipe, liens
  Google Maps et réservation, bons plans 🔥 en surbrillance),
  Budget (prévu vs réel avec graphique, saisie de dépenses),
  Checklist (items cochables avec persistance)
- /trip/[token] : Vue publique read-only partageable sans login

DESIGN : Dark mode (#0B1929), accents orange (#FF6348, #FFA502), vert (#1DD1A1).
Font Nunito + Playfair Display. Mobile-first (max-width 520px). Animations fadeIn.
Cards avec glassmorphism subtil.

FEATURES CLÉS :
- Génération IA d'itinéraires via Claude API (JSON structuré)
- Bons plans perso 🔥 (is_personal) visuellement distincts
- Carte Leaflet interactive avec tiles CartoDB dark
- Budget dynamique : prévu (calculé) vs réel (saisi par le client)
- Checklist persistante
- Météo par ville (OpenWeatherMap API)
- Liens Google Maps sur chaque activité
- Liens de réservation optionnels
- Swipe gauche/droite entre les jours
- Lien de partage public (share_token)
- Export PDF de l'itinéraire
- PWA installable
```
